# 代码修复指南：恢复"点击行定位"功能

> 背景：定位功能 v1（整行点击版）用户实测**可用**；用户发送"复制按钮/提示文案"
> 反馈后（下称 v2 改动）定位失效；其后 v3（行号点击版）仍失效。
> 本文档给出：回归窗口内全部 diff、根因分析、**v1 已验证代码原文**、修复步骤。
> 本文档只描述修复方案，未改任何代码。

## 1. 三个版本与回归窗口

| 版本 | 交互设计 | 用户实测 |
|---|---|---|
| v1 | onclick 挂 **li 整行**；textarea `stop_propagation`；复制按钮无 stop_propagation | ✅ **可以定位**（用户确认） |
| v2 | 仅改：按钮升标准尺寸+文案"⧉ 复制"、**给按钮 onclick 加了 stop_propagation**、CSS `li.line .btn-sm`→`li.line > button`、3 条 i18n 文案 | ❌ 定位失效（用户报告） |
| v3 | onclick 从 li 移到**行号 span**（.row-no.locatable）；删 li onclick 与 textarea/按钮的 stop_propagation | ❌ 仍失效（用户报告） |

**结论：回归由 v2 引入**（v1→v2 之间只发生了：i18n 迁 JSON（用户确认当时定位还好的构建已含 JSON 版）、v2 四处小改）。v3 是在错误前提下（"点击目标不可达"）的二次改动，未修复说明当初判断有误。

## 2. v2 的四处 diff 与嫌疑分析

### diff①（头号嫌疑）：复制按钮 onclick 加了 stop_propagation

```rust
// v1（可定位）：
button { class: "btn-sm", title: "{t(i18n::k::COPY_ROW_TIP)}",
    onclick: move |_| match copy_text(&copy_text_v) { ... },
    "⧉" }

// v2（失效）：
button { title: "{t(i18n::k::COPY_ROW_TIP)}",
    onclick: move |e| {
        e.stop_propagation();          // ← 新增：阻断冒泡到 li
        match copy_text(&copy_text_v) { ... }
    },
    "⧉ 复制" }
```

**机理**：v1 中 li 的 onclick 靠**事件冒泡**接收行内几乎所有点击——textarea 被
stop_propagation 挡住，但**行号、分数、行内边距、复制按钮**的点击全部冒泡到 li
→ 触发定位。v2 给按钮加 stop_propagation 后，按钮这一大块（升标准尺寸后更大）
不再触发；行边距剩余可点区域变得极窄。**用户 v1 时期"点行能定位"的点击点，
大概率落在按钮或行尾区域**——v2 后同一位置点击只复制不高亮，表现即"不能定位了"。

### diff②（无事件影响，可排除）：CSS 选择器

`li.line .btn-sm` → `li.line > button`。纯布局（flex: 0 0 auto 的挂靠对象变了），
不影响事件。随 v1 按钮结构一并回退即可。

### diff③（可排除）：i18n 三条文案内容
`main.results_head` / `sta.recognize_done` / `locate.tip` 只改了文字，不参与事件。

### diff④（次要嫌疑）：v3 的行号 span onclick 本身
若按 §4 修复 A 恢复 v1 后**仍**不能定位，则 span/li 都不是问题，断点在
信号→渲染下游，走 §5 日志分流。目前无证据指向下游（v1 同一套渲染代码工作过）。

## 3. v1 已验证代码原文（恢复基准）

`ui/src/main.rs` OcrRow 组件（v1 全文，直接对照恢复；`// ←` 标注与现状的差异点）：

```rust
fn OcrRow(
    view: RowView,
    mut texts: Signal<Vec<String>>,
    mut copied: Signal<(String, u64)>,
    mut status: Signal<String>,
    mut locate: Signal<Option<(usize, [f32; 4])>>,
    lang: Signal<String>,
) -> Element {
    let lang_v = lang();
    let t = |k: &'static str| i18n::ts(&lang_v, k);
    let no = view.no;
    let idx = no - 1;
    let rows = est_rows(&view.text);
    let copy_text_v = view.text.clone();
    let copied_word = t(i18n::k::BTN_COPIED).to_string();
    let locate_box = view.box_px;
    let locate_tip = if view.box_px.is_some() {
        t(i18n::k::LOCATE_TIP).to_string()
    } else { String::new() };
    rsx! {
        li {
            key: "{no}",
            class: "line",
            title: "{locate_tip}",                       // ← v3 移到了 span，恢复到 li
            onclick: move |_| {                          // ← v3 移到了 span，恢复到 li
                let Some(b) = locate_box else { return; };
                let off = matches!(locate(), Some((n, _)) if n == no);
                locate.set(if off { None } else { Some((no, b)) });
            },
            span { class: "row-no", "{no}" }              // ← 恢复纯行号（v3 的
                                                          //    .locatable 类可留可删）
            textarea {
                class: "line-edit",
                rows: "{rows}",
                value: "{view.text}",
                onclick: move |e: MouseEvent| e.stop_propagation(),  // ← v1 必需：
                oninput: move |e| {                      //    挡编辑区点击冒泡
                    let v = e.value();
                    texts.with_mut(|list| {
                        if idx < list.len() { list[idx] = v; }
                    });
                },
                onkeydown: move |e: KeyboardEvent| {
                    if e.modifiers().contains(Modifiers::CONTROL)
                        && e.key() == Key::Character("v".into()) {
                        e.stop_propagation();
                    }
                },
            }
            span { class: "score", "{view.score}" }
            button { title: "{t(i18n::k::COPY_ROW_TIP)}",
                // 保留用户要求的标准尺寸与"⧉ 复制"文案，但【必须去掉
                // stop_propagation】——v1 正是靠这里的冒泡让行尾点击触发定位
                onclick: move |_| match copy_text(&copy_text_v) {
                    Ok(()) => copied.set((format!("row-{no}"), view.tick + 1)),
                    Err(e) => status.set(i18n::fill(i18n::tt(i18n::k::COPY_FAIL), e)),
                },
                "⧉ 复制" }
            if view.flash {
                span { class: "copied-chip", key: "{view.tick}", "{copied_word}" }
            }
        }
    }
}
```

## 4. 修复步骤（推荐路径 A）

1. 按上节恢复 OcrRow（li onclick + li title + textarea stop_propagation +
   按钮无 stop_propagation）。保留按钮标准尺寸与"⧉ 复制"文案（用户明确要求）。
2. （可选）删除或保留两处 `[locate]` 诊断 eprintln（onclick 内与
   `locate_view()` 内）——建议保留到用户确认修复后再删。
3. `cargo build -p rumi-ui && cargo test -p rumi-ui`（基线 57 passed + 1 ignored）
4. `pkill -x rumi-ui; nohup ./target/debug/rumi-ui > ui_run.out 2>&1 &`
5. 用户实测：识别 → 点行内任意非文本区域（行号/分数/行边距/复制按钮）→
   预览图出现蓝色定位框；再点同号消失。

**语义说明**：恢复 v1 后"点复制按钮"会同时 复制+切换定位高亮（v1 原行为，
用户按受）。若想分离，给按钮加回 stop_propagation 但**同时保留 li onclick**
（行其余区域仍可定位）——这是 v1 与 v2 的折中，见 §6。

## 5. 若路径 A 仍失效：日志分流（插桩已在当前构建里）

当前运行版已埋两处 `eprintln!`（输出在 `ui_run.out`）。点一次行首数字后：

| 日志现象 | 结论 | 修法 |
|---|---|---|
| 无 `[locate] click` | onclick 未触发 | 事件挂靠问题：确认 onclick 真在渲染出的元素上；WebKitGTK 下给 span/li 换 onmousedown 试试 |
| 有 click、无 `[locate] view` | locate.set 后 MainTab 未重渲染 | 信号订阅断：把 MainTab 中 `locate()` 的读取移到组件体顶层 `let loc_v = locate();` 再进 rsx；或改用 use_effect 监听 |
| click + view `-> None` | 尺寸守卫未过 | 看 `size=`/`disp=` 值：shot_size 为 0（未识别？）或 img_px<1（onmounted 时序）|
| click + view 有坐标 | 渲染了但不可见 | CSS：确认预览 wrapper `position:relative`、`.loc-rect` 的 z-index 高于 img、无 overflow 裁剪 |

## 6. 备选：折中交互（若用户不想要"按钮点击也切换定位"）

- li onclick 保留（行号/分数/边距可定位）
- 复制按钮保留 stop_propagation（点按钮只复制）
- 行号 span 加 `.locatable` 样式（v3 的视觉提示保留）作为"官方"定位点击点

此组合 = v1 的大点击区 + v3 的显式提示 + 按钮行为纯净，但**先走路径 A**
确认回归根因是 diff① 后再决定是否精细化。

## 7. 教训（写给后续改动）

1. 改交互前先记录"当前已验证可用"的代码原文（本次靠会话历史才复原）。
2. `stop_propagation` 是事件冒泡链上的破坏性改动——上游（li onclick）依赖
   冒泡时，给任一子元素加它都等于砍掉上游的一块触发区。改前 grep 同一子树
   的所有 onclick。
3. 开发者无法点击 GUI 验证 → 任何交互改动必须先埋日志、请用户点一次、
   看日志再收工。

## 8. 结局（2026-10-27 当日插桩实测，本文理论被否证）

本文 §2 的 diff①（stop_propagation 回归论）**被日志否证**，路径 A 未采纳：

1. **交互层从未断**：v3 行号 span 的 onclick 完全正常——插桩日志
   `[locate] click no=N box=Some([...])` 每次点击齐全（本文 §5 表第 1 行排除）。
2. **真实断点在 §5 表第 3 行**：`[locate] view ... disp=(0.0,0.0) -> None`
   ——预览图显示尺寸（img_px）恒为 0，被 locate_view 的尺寸守卫拦下。
3. **根因（异步竞态）**：onmounted 的 `get_client_rect` 是 evaluate_script
   异步查询，快照取于挂载瞬间（img 未解码 → wrapper 0×0）、结果晚到 ~30ms，
   把 ResizeObserver（onresize 事件）**已送达的真实尺寸覆盖回 0×0**。
   修法：wrapper 挂 `onresize` 唯一维护 img_px，onmounted 只存句柄不写值。
4. **"v1 曾可用"的解释**：v1 验证会话里用户先测过划选复制（P1 #9 同波功能），
   mousedown 重采把 img_px 治好过一次 → 行点击出框；v2/v3 测试会话直接
   OCR→点行 → 竞态必现 → 失败。时间相关，与 stop_propagation 无关。
5. **已验证**：用户真机点行号 1-5，全部 `-> Some((l,t,w,h))` + 截图确认
   蓝框可见、位置正确；测试基线 57+1 保持。
